Assignment 4

This assignment has taken a few different turns. I started with the work in Part4.ipynb and wanted to
get the forecast into the app without making it too complicated. I decided to make a separate page
for it, since the controls and the forecast plot would not fit very well on the other pages. It took
some testing to get it to use the selected area and date in the way I wanted.

On the new page, the user can choose how much history to use and how many weeks to forecast. The
date selected on the map is used as the end of the training period, so the map and forecast are
connected. I kept the data weekly. It matches the reservoir data and means the model does not have
to work through an unnecessary amount of information.

I also added temperature and precipitation as things the model can use when making a prediction.
This was a bit tricky, because the model needs weather data for the weeks it is forecasting too.
There is no actual weather forecast for all of that time, so for now I use the same weeks from the
previous year as a rough estimate. It is not perfect, but it lets me try the model with weather data
and is clear about what is being assumed. The forecast is animated, which makes it easier to follow
how the predicted filling changes week by week.

Another thing I worked on was making the waiting less confusing. Some of the data takes time to
load, and before it could be hard to tell if the app was still working. There is now progress shown
while weather data is downloaded, and a loading sign over the map when it updates. I also added
caching in the places that were repeatedly downloading or calculating the same things. The first
load can still take a little while, but going back to the same data should be quicker.

I tested the page with made-up reservoir and weather data, and checked that it works both with and
without weather variables. I also checked that the plots appear and that the loading progress and
caching still work. This was useful for finding problems without relying on the real APIs every time.
It does not tell me how accurate the forecast will be with real future weather, so that part still
needs to be treated carefully.

There was a lot to connect, but I think keeping the page separate and the choices understandable
made the end result easier to use.

This assignment was a battle with the APIs. It started right away with the weather data. First I used the 
wrong one (forecast data). Then I found the historical weather data, but after a while I realised it only 
covered the last 16 days. Then I found the historical archive, which goes back to 2007. But this one didn’t 
work either, unlike the previous ones. After hours of testing and asking AI, I understood that the maximum 
daily credit limit had been used.

Moving on, the functions for handling weather data were easier to deal with. I made some test data so that 
I was not dependent on the actual data from Open-Meteo, and this worked great.

After defining the functions, I found that hourly resolution was not great for the plots, so I changed it 
to daily averages. However, the outliers and anomalies are still detected on the hourly data, so only the 
plots look different.

The app has many changes, as expected. The biggest is the new pages. I have reservoir and weather on 
separate pages, and each of them has two pages: one where the data is loaded, and another where the 
data is analysed. The analysis includes parameters to interact with and change, and some plots to visualise 
them.

I added a global area selector on the left, under the page menu. The names have been changed from the 
previous assignment to make more sense and be more compact.

It was also necessary to reorder the pages and rename some of them.

There was a lot of implementation this round, and many places to mess up. From testing, it works as I would 
expect, and I have had to edit the code and logic more than once. Hopefully, it’s good now.
